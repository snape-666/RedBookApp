# Taste
- Communicates in Chinese; prefers responses and discussion in Chinese. Confidence: 0.8
- Prefers to replicate the structure and layout logic of an existing screen when creating a new similar page, to keep the UI consistent across related screens — explicitly endorses copying existing code directly (e.g., "代码可以直接照搬") when a new page mirrors an existing one. Confidence: 0.95
- Prefers using the project's theme color helper functions (e.g., getOutline, getOnSurfaceSecondary, getOnSurfaceTertiary) rather than hardcoded colors. Confidence: 0.9
- When specifying a UI screen, gives precise pixel-level specs (exact dp spacing, corner radii, max-width ratios, color tokens) and expects the implementation to match them exactly. Confidence: 0.85
- Prefers compact controls that hug their content: input bars should be roughly text height plus small padding (e.g., 5dp vertical), not the taller default Material paddings, and sibling controls (e.g., a send button next to an input field) should be equal height. Confidence: 0.6
- Expects standard keyboard UX on input/chat screens: the IME keyboard pushes the content up (imePadding) and tapping blank space dismisses the keyboard. Confidence: 0.7
- For pages backed by cloud data, expects a ViewModel + ViewModelFactory wired through navigation, with optimistic UI updates that sync to the backend. Confidence: 0.6
- Prefers unread-count badges to be circular, with the theme primary color as background and surface color for the digits, anchored at the top-right corner of the icon (and the same badge style on the bottom "消息" nav tab when a private message arrives), matching WeChat/Xiaohongshu conventions. Confidence: 0.8
- Prefers social interactions (likes, favorites, follows, comments, private messages) to be real-time and backed by the backend rather than locally simulated/mock data. Confidence: 0.85
- Validates real-time/social features end-to-end with a second account: performs the action from another account, switches accounts, and expects the notification list, unread badges, and chat to reflect it immediately. Confidence: 0.7
- When a feature "doesn't work" (e.g., a feed shows empty though the user knows data was published), expects the assistant to verify the actual live backend state and data source (e.g., which Supabase table holds the rows, whether the query targets the right table) and find the root cause, not just confirm local builds pass. Confidence: 0.65
- Full-screen content pages (e.g., Douyin-style video feed) must always show a top bar with a back button — including in loading and empty ("暂无…") states — so the user can always exit; an empty state with no way to navigate back is a bug. Such pages must also be pushed onto the navigation back stack (navigateTo) when opened from a tab/main screen — replacing the entire stack turns the page into a root with nothing to go back to, so the back button/goBack silently does nothing and the user reports it as "no back icon". Confidence: 0.8
- Prefers buttons whose label can change (e.g., 关注 → 已关注 → 发私信) to keep a fixed width with centered content and constant internal padding, so changing the text length never changes the button width or shifts the layout. Confidence: 0.85
- On user-list rows (e.g., followers), the follow state must be reflected correctly and be toggleable: an un-followed user must show a "关注" button (not "发私信" — showing 发私信 for someone you don't follow is a bug), and the row keeps a single fixed-width button whose label switches between 关注 and 发私信 based on follow state — do NOT add extra icons next to the follow button (the user explicitly rejected such an icon). Follow actions must toggle the current state (!followed) rather than hardcode to "follow". Confidence: 0.8
- Expects account-to-account messaging bridges wherever another user is surfaced (follower list rows, post-detail author bar): tapping "发私信" directly creates/opens the conversation with that user and lands on the corresponding ChatScreen. Confidence: 0.6
- In chat screens, prefers avatars to show on both sides: own sent messages display the current user's avatar on the right and peer messages display the peer's avatar on the left — sent messages should not appear avatar-less. Confidence: 0.7
- Expects account switching to be clean and leak-free: session-scoped chat state (peerUid, conversationId) must reset on logout, and account-scoped ViewModels/lists (conversations, notifications) must reload for the new account — seeing the previous account's data or a broken send button after switching accounts is a bug. Confidence: 0.6
- In the conversation list row, prefers the unread-count badge at the end of the second row (right of the last-message preview, aligned to the row end, WeChat style) — explicitly NOT overlaid on the avatar's top-right corner — and keeps it small/compact (e.g., ~18dp circle, ~9sp digits). Confidence: 0.8
- Messaging time display follows a fixed relative-time hierarchy: today shows HH:mm → 昨天 → 前天 → N天前 → N周前 → N月前 → older than a year shows yyyy-MM-dd; the same hierarchy should be applied consistently in both the conversation list and the chat screen. Confidence: 0.85
- In chat screens, mimics WeChat timestamp behavior: inserts a small centered time divider between adjacent messages when the gap exceeds ~5 minutes instead of stamping every message. Confidence: 0.7
- In chat, the sender's avatar must remain visible regardless of message length — long messages should wrap within a capped-width bubble rather than expanding the row and pushing the avatar off-screen. Confidence: 0.75
- When checking in on a multi-item request ("我说的任务完成了吗"), expects the assistant to track the requested items (e.g., a todo list) and report precisely which are done and which remain, then finish the remaining ones — not just claim "almost done". Confidence: 0.5
- For real user-generated content in lists (e.g., notification actor avatars, post cover thumbnails), expects the actual network data to be loaded and displayed (query the users table for the avatar, the post's image_url for the cover) rather than a hardcoded placeholder drawable; placeholders only as a fallback when loading fails. Confidence: 0.75
- In chat, prefers optimistic media sending: the sender's image/video bubble appears immediately using the local content URI and is swapped for the remote URL once upload completes, so the sender never sees their own sent media vanish or fail to render. Confidence: 0.65
